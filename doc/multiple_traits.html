Combine several traits as constraints

Maël Doré

2026-11-26

Grafting can be constrained by species attributes described by stochastic character maps (simmap) of the backbone phylogeny. This tutorial explains how to use several traits at once, e.g., the color and the elevation of the species, or their biogeographic ranges and their elevation. The rule is simple: a taxon can only be grafted on the parts of the branches that are in one of its allowed states, for every trait. The more traits you use, the narrower the set of eligible branches is.

In this tutorial, we cover:

  1. How to provide the maps and the allowed states of several traits.
  2. The joint effect of the constraints, checked with check_grafting_plan().
  3. Grafting with two categorical traits.
  4. Grafting with one trait treated as biogeographic ranges and one other trait.
  5. Several maps per trait.

Other types of data

The principle of species attribute-based constraints is the same for all the types of data. For examples addressing different data types, please refer to:

  • categorical traits (single trait): vignette("main_workflow"), and the examples of vignette("graft_missing_taxa"), vignette("graft_missing_clades") and vignette("combine_missing_taxa_and_clades");
  • biogeographic ranges (multi-area states, treat_states_as_ranges): vignette("biogeographic_data");
  • continuous traits: vignette("continuous_data");
  • several stochastic maps to account for the uncertainty in the evolutionary history: vignette("handle_uncertainty").

To build stochastic maps from your own data, see vignette("prepare_stochastic_maps").

0/ Data

We use the toy backbone, and the toy stochastic maps of two categorical traits: a color with three states ("blue", "green", "red") and an elevation with two states ("low", "high"). Both maps have the same tips, topology and branch lengths as the backbone, as required.

The maps are provided to the grafting functions in a list with one map per trait: simmap = list(color = toy_simmap, elevation = toy_simmap_elevation). Naming the elements is optional (the traits are otherwise called "trait_1", "trait_2", …), but it makes the allowed states and the outputs easier to read. Names cannot contain ;, ,, = or |.

1/ Allowed states of several traits

The allowed states are set of states for each trait, provided as with a single trait:

  • for all the taxa, with the global argument allowed_states, here as a list with one element per trait, in the order of the maps. Ex: list(c("blue", "green"), "high") restricts the color to blue or green and the elevation to high.
  • for each taxon, with the item allowed_states of the missing_taxa_list: it has the same structure, and its values supersede the global ones, trait by trait.

A trait with NULL (or an empty vector, or NA) has no taxon-level value, so the global value of the trait is used. If there is no global value either, all the states of the trait are allowed.

Below, we print as a reference the taxon-level values of the 7 missing taxa of the toy list, for each trait:

# ------ Allowed states of two traits for each taxon ------ #

# Rename the loaded missing_taxa_list for simplicity
taxa_two_traits <- toy_missing_taxa_list_with_two_traits

# Helper: extract the taxon-level allowed states of one trait
# Elements of the list are either named after the traits, or in the order of the maps
get_allowed <- function(taxa, trait_name, trait_index)
{
  vapply(taxa$allowed_states, function(x)
  {
    values <- if (is.null(names(x))) x[trait_index][[1]] else x[[trait_name]]
    if (is.null(values)) "NULL" else paste(values, collapse = ", ")
  }, character(1))
}

# Build and print allowed states as a data.frame
data.frame(Taxon_name = taxa_two_traits$Taxon_name,
           Color = get_allowed(taxa_two_traits, "color", 1),
           Elevation = get_allowed(taxa_two_traits, "elevation", 2),
           row.names = NULL)
#>   Taxon_name       Color Elevation
#> 1    New_sp1         red      NULL
#> 2    New_sp2        NULL      NULL
#> 3    New_sp3        NULL      NULL
#> 4    New_sp4 blue, green      high
#> 5    New_sp5        NULL       low
#> 6    New_sp6        NULL      NULL
#> 7    New_sp7        NULL      high

# NULL will be using the global 'allowed_states' provided to the grafting function

In a .csv or .xlsx table imported with import_missing_taxa_list() (see vignette("format_inputs")), the allowed_states column uses a compact syntax:

  • sets of states for each trait are separated by semicolons, in the order of the maps (the color, then the elevation);
  • the states within a trait are separated by commas.

In the missing_taxa_list, $allowed_states is a list of (named) character vectors (e.g., list(color = c("red", "blue"), elevation = "low")). See Section 2 below for an example of how to modify the list manually.

For illustration, we print the allowed_states column of the .csv table used to build the toy list (taxa_two_traits <- toy_missing_taxa_list_with_two_traits) loaded above:

# The initial table of the toy list
csv_file <- system.file("extdata", "toy_missing_taxa_with_two_traits.csv", package = "phylograftR")
csv_table <- read.csv(csv_file)
csv_table[, c("Taxon_name", "allowed_states")]
#>   Taxon_name   allowed_states
#> 1    New_sp1             red;
#> 2    New_sp2                 
#> 3    New_sp3                 
#> 4    New_sp4 blue, green;high
#> 5    New_sp5             ;low
#> 6    New_sp6

The syntaxes illustrated by the toy table are:

In the table Meaning
red; color "red", no taxon-level value for the elevation (global value used)
blue, green;high color "blue" or "green", and elevation "high"
;low no taxon-level value for the color, elevation "low"
elevation=high traits named, so the color can be omitted (no taxon-level value)
blank no taxon-level value for any trait: the global allowed_states is used for both

The names of the traits must match the names of the maps in simmap to use the syntax with names.

2/ Joint effect of the constraints

check_grafting_plan() reports, for each taxon, the share of the branches of its target clade that are available given all its constraints (valid_fraction). To see the joint effect of the two traits, we compare the grafting plan with the constraints on the color only, on the elevation only, and on both.

In the toy list, the taxa are mostly constrained by one trait only. To illustrate the joint effect of the traits, we add elevation constraints to three taxa, so that the elevation is a limiting factor for them, and not only the color:

  • New_sp1 is allowed in red (as before) and now also in high elevation;
  • New_sp3 is allowed in the global colors (blue or green) and now also in low elevation;
  • New_sp4 is now allowed in blue (instead of blue or green) and in high elevation.

We update the list of missing taxa, and use this updated list for the rest of the tutorial.

# ------ Add elevation constraints to three taxa ------ #

taxa_two_traits$allowed_states$New_sp1 <- list(color = "red", elevation = "high")
taxa_two_traits$allowed_states$New_sp3 <- list(color = NULL, elevation = "low") # NULL: the global colors are used
taxa_two_traits$allowed_states$New_sp4 <- list(color = "blue", elevation = "high")
# ------ Valid fraction with the color only, the elevation only, and both ------ #

# Helper: keep the taxon-level allowed states of one trait only
keep_trait <- function(taxa, trait, traits = c("color", "elevation"))
{
  taxa$allowed_states <- lapply(taxa$allowed_states, function(x)
  {
    if (is.null(x)) return(NULL)
    out <- setNames(vector("list", length(traits)), traits)
    for (i in seq_along(x))
    {
      name <- if (is.null(names(x))) traits[i] else names(x)[i]
      out[name] <- list(x[[i]])
    }
    out[setdiff(traits, trait)] <- list(NULL)
    if (all(vapply(out, is.null, logical(1)))) NULL else out
  })
  taxa
}

# Set the global allowed states: blue or green for the color, no restriction for the elevation
global_allowed_states <- list(c("blue", "green"), NULL)

# Check grafting plan with colors only
plan_colors <- check_grafting_plan(phy = toy_backbone, 
                                   missing_taxa_list = keep_trait(taxa_two_traits, "color"),
                                   simmap = maps_color_elevation,
                                   allowed_states = global_allowed_states, verbose = FALSE)
# Check grafting plan with elevation only
plan_elevation <- check_grafting_plan(phy = toy_backbone, 
                                      missing_taxa_list = keep_trait(taxa_two_traits, "elevation"),
                                   simmap = maps_color_elevation,
                                   allowed_states = list(NULL, NULL), verbose = FALSE)
# Check grafting plan with both
plan_both <- check_grafting_plan(phy = toy_backbone, 
                                 missing_taxa_list = taxa_two_traits,
                                 simmap = maps_color_elevation,
                                 allowed_states = global_allowed_states, verbose = FALSE)

# Extract the valid fractions for each plan
valid_fractions <- data.frame(Taxon_name = taxa_two_traits$Taxon_name,
  Color_only = plan_colors$valid_fraction,
  Elevation_only = plan_elevation$valid_fraction,
  Both = plan_both$valid_fraction)
valid_fractions[, -1] <- round(valid_fractions[, -1], 2)

#> 2    New_sp2       0.31           1.00 0.31
#> 3    New_sp3       0.52           0.20 0.11

The traits do not constrain all the taxa in the same way:

  • For New_sp2, New_sp5, New_sp6 and New_sp7, the color is the limiting constraint and the valid fraction with both traits is the one of the color. Their elevation is not restrictive (Elevation_only of 1): either they have no elevation constraint (New_sp2, New_sp6) or all their eligible branches are already in the allowed elevation (New_sp5, New_sp7: e.g., once the excluded subclade Gen_1 is removed, all the branches left for New_sp5 are in low elevation).
  • For New_sp1, New_sp3 and New_sp4, the traits interact: both constrain the grafting to a restricted portion of available branches, and the branch pieces that match both constraints are much rarer than those matching each of them (14%, 11% and 4% of branch length, respectively), since the states of the two traits are not aligned along the branches (see the simmaps in Section 0 above).

In general, the more traits are combined, the more likely a taxon has few or no eligible branches. Therefore, it is recommended to use check_grafting_plan() to evaluate the feasibility of the grafting plan beforehand.

Here, the valid fraction of New_sp4 is below the threshold min_valid_fraction (10% by default), which triggers a warning at grafting (see vignette("check_grafting")). Nonetheless, the grafting plan is still feasible.

3/ Graft with two categorical traits

We graft the 7 taxa with the global allowed_states = list(c("blue", "green"), NULL). The grafting warns about New_sp4, as anticipated by the plan in Section 2: allowed branches cover only about 4.8% of the time window of its divergence ages, so its age is drawn within a narrow window, and may need to be redrawn many times until a suitable divergence ages is found.

# ------ Graft with two categorical traits ------ #

grafted_two_traits <- graft_missing_taxa(phy = toy_backbone, missing_taxa_list = taxa_two_traits,
                                         simmap = maps_color_elevation,
                                         allowed_states = list(c("blue", "green"), NULL),
                                         verbose = FALSE, seed = 4)
#> Warning: 1 taxa have less than 10% of the time window of their divergence ages covered by available branches in their allowed states ('min_valid_fraction' = 0.1): their divergence ages will be concentrated on a narrow time window, or many ages will need to be redrawn.
#>   - New_sp4 (target clade tips: t8, t22; 4.86% in allowed states)

# The output has one updated simmap per trait, named after the traits
names(grafted_two_traits$simmap)
#> [1] "color"     "elevation"

In each updated simmap, the grafted branches are entirely in the state of each trait at the point where they were grafted: each trait is inherited from the lineage the taxon was grafted on. We plot the two updated maps, with the grafted tips marked with a point in the color of their state:

# ------ Compare the updated maps of the two traits ------ #

# Helper: plot the updated simmap of one trait of a grafted phylogeny
plot_trait <- function(phy_grafted, trait, colors, main)
{
  plot_grafted(phy_grafted, which = "edges", trait = trait, simmap_colors = colors, fsize = 0.55, main = main)
  grafted_tips <- which(phy_grafted$grafted_tips)
  tip_states <- phytools::getStates(phy_grafted$simmap[[trait]], type = "tips")[phy_grafted$tip.label[grafted_tips]]
  ape::tiplabels(tip = grafted_tips, pch = 19, cex = 1.5, col = colors[tip_states])
}

par(mfrow = c(1, 2), mar = c(0.5, 0.5, 2, 0.5))
plot_trait(grafted_two_traits, trait = "color", colors = color_colors, main = "A: Color")
plot_trait(grafted_two_traits, trait = "elevation", colors = elevation_colors, main = "B: Elevation")

par(mfrow = c(1, 1), mar = c(5.1, 4.1, 4.1, 2.1))

4/ Graft with one trait treated as ranges

One of the traits can be treated as biogeographic ranges (see vignette("biogeographic_data")), and combined with any number of other traits.

Here, we combine the toy biogeographic ranges ("A", "B", "AB", "BC") and the elevation:

# ------ Toy data: ranges and elevation ------ #

data(toy_simmap_ranges)
data(toy_missing_taxa_list_with_ranges_and_elevation)

# Rename the missing taxa list for consistency
taxa_ranges_elevation <- toy_missing_taxa_list_with_ranges_and_elevation
# Combine simmap for biogeographic ranges and elevation
maps_ranges_elevation <- list(biogeo = toy_simmap_ranges, elevation = toy_simmap_elevation)

# Print in a data.frame the taxon-level allowed states of the two traits
data.frame(Taxon_name = taxa_ranges_elevation$Taxon_name,
           Ranges = get_allowed(taxa_ranges_elevation, "biogeo", 1),
           Elevation = get_allowed(taxa_ranges_elevation, "elevation", 2),
           row.names = NULL)
#>   Taxon_name Ranges Elevation
#> 1    New_sp1      A      high
#> 2    New_sp2   NULL      NULL
#> 3    New_sp3   NULL      NULL
#> 4    New_sp4  B, BC      NULL
#> 5    New_sp5   NULL       low
#> 6    New_sp6   NULL      NULL
#> 7    New_sp7  A, BC      high

# NULL will be using the global 'allowed_states' provided to the grafting function

The argument treat_states_as_ranges is a logical vector with one value per trait, with at most one TRUE that identifies the range trait. It is either positional (c(TRUE, FALSE): the first trait is the range trait) or named after the traits, in any order (c(biogeo = TRUE, elevation = FALSE)).

  • The range trait follows the logic of range matching: a taxon allowed in "A" can be grafted on branch pieces in "A", "AB" or "ABC", and inherits one of its allowed range.
  • The other traits are matched exactly, and are inherited as they are at the point where the taxon is grafted.

Only one trait can be treated as ranges, to prevent an inflation of the number of combined states to consider.

Here, we graft the taxa, with the global allowed ranges "A" or "B", and no restriction on the elevation:

# ------ Graft with ranges and elevation ------ #

grafted_ranges_elevation <- graft_missing_taxa(phy = toy_backbone, 
                                               missing_taxa_list = taxa_ranges_elevation,
                                               simmap = maps_ranges_elevation,
                                               allowed_states = list(c("A", "B"), NULL),
                                               treat_states_as_ranges = c(biogeo = TRUE, elevation = FALSE),
                                               verbose = FALSE, seed = 9)
# ------ Compare the updated maps of the two traits ------ #

range_colors <- c(A = "gold", B = "dodgerblue", AB = "limegreen", BC = "firebrick2")

par(mfrow = c(1, 2), mar = c(0.5, 0.5, 2, 0.5))
plot_trait(grafted_ranges_elevation, trait = "biogeo", colors = range_colors, main = "A: Ranges")
plot_trait(grafted_ranges_elevation, trait = "elevation", colors = elevation_colors, main = "B: Elevation")

par(mfrow = c(1, 1), mar = c(5.1, 4.1, 4.1, 2.1))

5/ Several maps per trait

Each trait can be described by several stochastic maps (a "multiSimmap"), to account for the uncertainty in its evolutionary history (see vignette("handle_uncertainty")). The maps of the traits are paired: the grafting is run with the map 1 of every trait, then with the map 2 of every trait, and so on. All the traits must therefore have the same number of maps.

This also applies to a trait described by a single simmap: it cannot be mixed with a trait described by a multiSimmap, and such a list is refused. You can always duplicate the single simmap in the list, so that it pairs with all the maps of the multiSimmap of the other trait. For instance, toy_multiSimmap_elevation[rep(1, 10)] repeats the map 1 of a multiSimmap 10 times and keeps the class "multiSimmap", which is essential to tell phylograftR that this set of maps are inferred for a unique trait (a list of simmaps, without the multiSimmap class, would be read as 10 unique maps for 10 different traits).

We quickly generate 10 stochastic maps for each trait with phytools::make.simmap(), from the states of the tips of the toy maps (equal-rates model). Of course, in a real analysis, the maps would be built from your own data (see vignette("prepare_stochastic_maps")).

# ------ 10 stochastic maps for the color and for the elevation ------ #

# States of the tips of each trait
tip_colors <- phytools::getStates(toy_simmap, type = "tips")
tip_elevations <- phytools::getStates(toy_simmap_elevation, type = "tips")

# Simulate 10 stochastic maps per trait
set.seed(33)
multi_color <- phytools::make.simmap(toy_backbone, tip_colors, model = "ER", nsim = 10, message = FALSE)
multi_elevation <- phytools::make.simmap(toy_backbone, tip_elevations, model = "ER", nsim = 10, message = FALSE)

# Group them in a named list, as with a single map per trait
multi_maps <- list(color = multi_color, elevation = multi_elevation)

With random maps, the constraints can differ a lot from one map to the next. check_grafting_plan() summarizes the valid fraction of each taxon across the pairs of maps (minimum, mean and maximum). It also reports the maps with no available branch for a taxon (n_maps_infeasible), which would stop the grafting:

# ------ Grafting plan across the 10 pairs of maps ------ #

plan_paired <- check_grafting_plan(phy = toy_backbone, missing_taxa_list = taxa_two_traits,
                                   simmap = multi_maps,
                                   allowed_states = list(c("blue", "green"), NULL), verbose = FALSE)

#> 4                 0     TRUE
#> 5                 0     TRUE

As in Section 2, the strict constraints leave few eligible branches for some taxa (e.g., New_sp1), especially in some maps.

Here, we graft with method = "uniform", which only requires an available branch in each map as the age of the grafting is not drawn from a diversification model. This is a solution when constrains are too strict to be easily realized under diversification models, but at the cost of ignoring diversification dynamics, which tend to create a bias towards older divergence ages (see Section 2 vignette("graft_missing_taxa")). It is not the recommended use of phylograftR, but is used here only as illustration.

We also silence the warnings about the low valid fractions already shown above by setting min_valid_fraction = 0, i.e., warnings are sent only if no branch pieces are available at all.

We generate 5 simulations for each pair of maps:

# ------ Graft with paired maps ------ #

grafted_paired <- graft_missing_taxa(phy = toy_backbone, missing_taxa_list = taxa_two_traits,
                                     simmap = multi_maps,
                                     allowed_states = list(c("blue", "green"), NULL),
                                     method = "uniform", min_valid_fraction = 0,
                                     nb_simulations = 5, seed = 1, verbose = FALSE)

The output is a list with one element per pair of maps ("map_1", "map_2", …), each being a multiPhylo of the 5 grafted phylogenies obtained with this pair:

Note that pairing the map 1 of a trait with the map 1 of the others is a choice of the analysis: the maps of two traits are usually built independently, so any pairing is arbitrary and does not represent a correlated evolution of the traits. If you want to cross every pair of maps instead, you can duplicate the maps in a dedicated fashion so that each map of the first trait meets each map of the second trait. With 10 maps per trait, repeat each map of the color 10 times in a row (map 1 x 10, then map 2 x 10, …), and repeat the whole series of maps of the elevation 10 times (maps 1 to 10, then again 1 to 10, …):

# ------ Not run: cross all the pairs of maps ------ #

# Each map of the color repeated 10 times in a row: c1, c1, ..., c2, c2, ..., c10
crossed_color <- multi_color[rep(1:10, each = 10)]
# The 10 maps of the elevation repeated 10 times: e1, ..., e10, e1, ..., e10, ...
crossed_elevation <- multi_elevation[rep(1:10, times = 10)]

# 100 pairs of maps = all the combinations of the 10 maps of each trait
grafted_crossed <- graft_missing_taxa(phy = toy_backbone, missing_taxa_list = taxa_two_traits,
                                      simmap = list(color = crossed_color, elevation = crossed_elevation),
                                      allowed_states = list(c("blue", "green"), NULL),
                                      nb_simulations = 5, seed = 1)

Beware of the rapid inflation of the number of grafted phylogenies!

Crossing all the maps multiplies the numbers of maps of the traits: here, 10 x 10 pairs of maps x 5 simulations = 500 phylogenies, instead of 50 with paired maps. In practice, 100 to 1000 stochastic maps per trait are typically used to account for the uncertainty in the evolutionary history. Crossing 100 maps per trait with 10 simulations each already gives 100 x 100 x 10 = 100,000 phylogenies, and crossing 1000 maps per trait up to 1,000,000 pairs of maps (10,000,000 phylogenies with 10 simulations each). Each additional trait multiplies this number again. Crossing every pair is therefore only realistic with a small number of maps, whereas pairing the maps (and a subset of them if needed) keeps the number of runs manageable.
