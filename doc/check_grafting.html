Check the grafting plan and the grafted phylogenies

Maël Doré

2026-11-26

Grafting is constrained (target clades, allowed states, …) and stochastic (divergence ages and positions are drawn from statistical distributions): it is worth checking that your grafting plan is feasible before grafting, that the constraints were respected after grafting. In addition, you may wish to check whether the resulting grafted phylogenies are consistent with what you expect in term of grafting positions, sampling fractions, and fit of diversification models.

This tutorial explains how to perform a priori and a posterior checks of grafted phylogenies, and detail how to read and interpret the outputs of the dedicated checking functions provided in the phylograftR package:

Function When What it tells you Section
check_grafting_plan() before grafting can each lineage be grafted with its constraints? 1
check_grafting_constraints() after grafting were all the constraints respected in each grafted phylogeny? 2
extract_grafting_info() after grafting where and when was each lineage grafted? 3
extract_sampling_info() after grafting what are the clade-specific sampling fractions after grafting? 4
extract_BD_model_summary() after grafting which birth-death models were used to draw the ages? 5

0/ Setup

We use the toy backbone with its toy stochastic map (one map), and 5 stochastic maps sampled from the tip data to illustrate the checks with many maps (see vignette("main_workflow") and vignette("prepare_stochastic_maps")).

Helper functions build the lists of missing taxa to graft.

data(toy_backbone)
data(toy_simmap)

# One map: toy_simmap (states: blue, green, red)

# Many maps: sample 5 stochastic maps from the tip data, with an equal-rates model of evolution
tip_data <- phytools::getStates(toy_simmap, type = "tips")
set.seed(1234)
simmaps <- phytools::make.simmap(tree = toy_backbone, x = tip_data[toy_backbone$tip.label],
                                 model = "ER", nsim = 5, message = FALSE)
class(simmaps)
#> [1] "multiSimmap" "multiPhylo"
# Helper 1: build a missing_taxa_list with n taxa to graft within a target clade defined by tips
make_taxa_list <- function(n, target_tips, prefix, allowed_states = NULL, start = 1)
{
  taxa <- paste0(prefix, seq(start, length.out = n))
  out <- list(Taxon_name = taxa, Target_clade = setNames(rep(list(target_tips), n), taxa))
  if (!is.null(allowed_states)) out$allowed_states <- setNames(rep(list(allowed_states), n), taxa)
  return(out)
}

# Helper 2: combine several lists of missing taxa
combine_lists <- function(...)
{
  lists <- list(...)
  out <- list(Taxon_name = unlist(lapply(lists, `[[`, "Taxon_name")),
              Target_clade = do.call(c, lapply(lists, `[[`, "Target_clade")))
  out$allowed_states <- do.call(c, lapply(lists, function(x)
  {
    if (is.null(x$allowed_states)) setNames(rep(list(NULL), length(x$Taxon_name)), x$Taxon_name) else x$allowed_states
  }))
  return(out)
}

1/ Before grafting: check_grafting_plan()

check_grafting_plan() verifies that each lineage can be grafted with its constraints, without grafting anything. For each taxon, it identifies the branches of its target clade available for grafting, after removing the excluded subclades; it checks that there are branch pieces in the allowed states in the stochastic map, and reports the proportion of branch pieces that are available for grafting within the time window of the target clade. It returns one row per taxon, and prints a summary.

The goal of this function is to evaluate potential issues before grafting and adjust the constraints before running any potentially time-consuming task that would be deem to failure.

Check the plan

Here, as an illustration, We build a list of five taxa to graft representing different situations:

  • Fam_blue1 and Fam_blue2: grafted within Family_B, in the state “blue”;
  • Small_sp1: grafted within Gen_1, a small clade of 3 tips;
  • Narrow_sp1: grafted within Subfam_B2, in the state “red”, which is rare in this clade;
  • Mistake_sp1: grafted within Gen_1, in the state “red”: a mistake, as no branch of this target clade is red.
# ------ Check the plan with one stochastic map ------ #

# Build the list of missing taxa
taxa_blue <- make_taxa_list(n = 2, target_tips = c("t8", "t22"), prefix = "Fam_blue",
                            allowed_states = "blue")
taxa_small <- make_taxa_list(n = 1, target_tips = c("t13", "t27"), prefix = "Small_sp")
taxa_narrow <- make_taxa_list(n = 1, target_tips = c("t5", "t22"), prefix = "Narrow_sp",
                              allowed_states = "red")
taxa_mistake <- make_taxa_list(n = 1, target_tips = c("t13", "t27"), prefix = "Mistake_sp",
                               allowed_states = "red")
taxa_list <- combine_lists(taxa_blue, taxa_small, taxa_narrow, taxa_mistake)

# Check the plan with the toy stochastic map
plan_one <- check_grafting_plan(phy = toy_backbone, missing_taxa_list = taxa_list, simmap = toy_simmap)
#> Grafting plan: 5 taxa
#>   - Can be grafted: 4/5
#>   - Cannot be grafted (1):
#>       allowed_states              1
#>       e.g., Mistake_sp1
#>   - Share of the available branches in allowed states (feasible taxa): min 4.3%, median 30.8%
#>   - Share of the time window with grafting possible (feasible taxa): min 5.5%, median 65.3%
#>   - Below 'min_valid_fraction' = 0.1 (1): Narrow_sp1
#>   - Target clades smaller than 'min_tips' = 5 (birth-death model fitted on an enclosing clade): 3/5; enclosing clades of 8 to 13 tips in the backbone; in practice, the clade used can be nested within them, as previously grafted taxa count towards 'min_tips'

#> 3   Small_sp1             3 blue, green, red     1.00000000     1.0000000
#> 4  Narrow_sp1             4              red     0.04276293     0.0547333

The summary reads from top to bottom:

  • Can be grafted: the number of taxa with at least one branch piece available in their allowed states. Here, Mistake_sp1 cannot be grafted (cause = "allowed_states"): it needs red branches, and there are none in Gen_1. Grafting stops with an error for such a taxon, so it must be fixed first (see below).
  • Share of the available branches in allowed states (valid_fraction) and share of the time window with grafting possible (time_coverage): how much room there is for grafting each taxon in average.
  • When the room is below min_valid_fraction (10% by default), the taxon can be grafted but only in a narrow place: Narrow_sp1 would always land in the same few branches (cause = "low_valid_fraction"). It is not a mistake, but this is reported here as you may wish to check that this is what you want, as this is a strong constraint on the placement of the missing taxon.
  • Target clades smaller than min_tips: the birth-death model that draws the divergence ages is fitted on the target clade, or on an enclosing clade if it has fewer than min_tips tips (5 by default). This reports how many cases of such changes in clades used for fitting diversification dynamics occurred. See the section on min_tips of vignette("graft_missing_taxa") for more information on enclosing clades. See Section 5 in this tutorial for how to use extract_BD_model_summary() to explore a posteriori the parameters and results of all Birth-Death (BD) models used during the run.

The output table provides causes for which each grafted taxon may lead to an error. The possible causes that make a taxon unfeasible are "allowed_states" (no branch piece available in the allowed states) and, when excluded subclades are used, "excluded", "excluded_contains_target" and "excluded_identical" (when the excluded subclades leave no branch to graft on). The cause "low_valid_fraction" is only a warning: the taxon is feasible, but the stochastic process may fail to draw a divergence age compatible with the available branch pieces.

# If you try to graft anyway, the grafting will stops with an informative error
# highlighting the taxon that could not be grafted
tryCatch(graft_missing_taxa(phy = toy_backbone, missing_taxa_list = taxa_list, simmap = toy_simmap,
                            seed = 1, verbose = FALSE),
         error = function(e) cat(conditionMessage(e)))
#> 1 taxa have no branch available for grafting in their allowed states: none of the available branches of their target clade has a piece in these states.
#>   - Mistake_sp1 (target clade tips: t13, t27; allowed states: red)
#> Adjust 'allowed_states' (global or in missing_taxa_list), or the constraints on the branches ('include_target_clade_stem', 'Excluded_subclades', 'exclude_subclades_stem') for these taxa.

Fix the plan

Here, we fix our grating plan by adjusting constraints to cover all potential issues:

  • we correct the allowed states of the mistaken taxon;
  • we widen the states of the narrow one;
  • we use min_tips = 3 to fit the model on the 3-tip clade Gen_1 instead of an alternative enclosing clade.
# Fix the allowed states
taxa_narrow_fixed <- make_taxa_list(n = 1, target_tips = c("t5", "t22"), prefix = "Narrow_sp",
                                    allowed_states = c("red", "green")) # Use red AND green as allowed states
taxa_mistake_fixed <- make_taxa_list(n = 1, target_tips = c("t13", "t27"), prefix = "Mistake_sp",
                                     allowed_states = "green") # use green instead of red
taxa_list_fixed <- combine_lists(taxa_blue, taxa_small, taxa_narrow_fixed, taxa_mistake_fixed)

# Check the fixed plan, with min_tips = 3
# By using a lower min_tips value, we ensure that the BD models are fitted strictly on our target clades
# However, as a trade-off, we may have lower accuracy in our estimates of diversification rates as we used smaller clades for fitting models
plan_fixed <- check_grafting_plan(phy = toy_backbone, missing_taxa_list = taxa_list_fixed,
                                  simmap = toy_simmap, min_tips = 3)
#> Grafting plan: 5 taxa
#>   - Can be grafted: 5/5
#>   - Share of the available branches in allowed states (feasible taxa): min 30.8%, median 82.8%
#>   - Share of the time window with grafting possible (feasible taxa): min 65.3%, median 100.0%
#>   - Target clades smaller than 'min_tips' = 3 (birth-death model fitted on an enclosing clade): 0/5
#>   => All can be grafted with these constraints

Check plan with many maps

The evolutionary history of a trait is uncertain. This uncertainty can be accounted for by providing phylograftR with multiple stochastic maps to constrain grafting using species-attributes (see vignette("handle_uncertainty") for more details).

As a consequence, a taxon can be feasible on some maps but not on others. With many stochastic maps, check_grafting_plan() checks each map, and summarizes them: it reports the taxa that are not feasible in all the maps, and the range of the room for grafting across the maps (valid_fraction_min, valid_fraction_mean, valid_fraction_max…), with the worst map being the one that limits the plan.

# ------ Check the plan with many stochastic maps ------ #

# Check grafting plan for all simmaps
plan_many <- check_grafting_plan(phy = toy_backbone, missing_taxa_list = taxa_list, simmap = simmaps)
#> Grafting plan: 5 taxa, 5 maps
#>   - Can be grafted in all the maps: 4/5
#>   - Cannot be grafted (1):
#>       allowed_states              1
#>       e.g., Mistake_sp1
#>   - Share of the available branches in allowed states (worst map, feasible taxa): min 6.6%, median 7.5%
#>   - Share of the time window with grafting possible (worst map, feasible taxa): min 8.5%, median 13.8%
#>   - Below 'min_valid_fraction' = 0.1 (3): Narrow_sp1, Fam_blue1, Fam_blue2
#>   - Target clades smaller than 'min_tips' = 5 (birth-death model fitted on an enclosing clade): 3/5; enclosing clades of 8 to 13 tips in the backbone; in practice, the clade used can be nested within them, as previously grafted taxa count towards 'min_tips'
#>   => Some cannot be grafted with these constraints (see the table)

# One row per taxon, summarizing the maps

The column n_maps_infeasible counts the maps in which the taxon cannot be grafted. Here, Mistake_sp1 is not feasible in 4 of the 5 maps (one map has red branches in the clade by chance), so it still must be fixed.

Note that Fam_blue1 and Fam_blue2 were fine with toy_simmap, but have a narrow room for grafting in the worst map.

When a taxon is unfeasible in some maps only, you can extend its allowed states, widen its target clade, or remove the maps that are not compatible with your constraints (only if you can justify it, as it modifies the uncertainty in ancestral trait inferrence that you want to propagate).

The details of checks for each map are in the attribute per_map:

per_map <- attr(plan_many, "per_map")

# Inspect issues with "Narrow_sp1" across all maps
per_map[per_map$Taxon_name == "Narrow_sp1", c("map", "valid_fraction", "time_coverage", "feasible", "cause")]

2/ After grafting: check_grafting_constraints()

Once the grafting is done, check_grafting_constraints() verifies a posteriori that each lineage of each grafted phylogeny respects its constraints: it is in the tree, within its target clade, outside of its excluded subclades, in its allowed states. Globally, it also checks that the backbone is preserved (same topology, branch lengths unchanged).

The constraints are read from the missing_taxa_list, and the states from the $simmap carried by each grafted phylogeny. The function accepts one grafted phylogeny, or the outputs of the grafting functions with many simulations and maps.

Check constraints with one map

Here, we graft the fixed list of missing taxa on the toy map with 10 simulations, and check them after grafting:

# ------ Check the constraints with one stochastic map ------ #

# Graft the missing taxa with the fixed list
grafted_one <- graft_missing_taxa(phy = toy_backbone, missing_taxa_list = taxa_list_fixed,
                                  simmap = toy_simmap, min_tips = 3,
                                  nb_simulations = 10, seed = 1, verbose = FALSE)

# Check the constraints
constraints_one <- check_grafting_constraints(phy_grafted = grafted_one, phy_backbone = toy_backbone,
                                              missing_taxa_list = taxa_list_fixed,
                                              use_excluded_subclades = FALSE)
#> 10 phylogenies checked (1 map(s)), 5 taxa each
#>   - Phylogenies respecting all the constraints: 10/10
#>   Violations, over all the phylogenies (number of taxa x phylogenies):
#>   - Missing from the grafted tree: 0
#>   - Target clade violated:          0
#>   - Excluded subclade violated:     0
#>   - Allowed states violated:        0
#>   - Backbone: preserved in 10/10 phylogenies, branch lengths shifted by max 9.06e-11 of backbone depth (tolerance = 1e-06)
#>   => All constraints respected

The summary counts the violations of constraints over all the taxa and all the grafted phylogenies, and report them in a printed summary:

  • taxa missing from the tree;
  • taxa outside of their target clade;
  • taxa in an excluded subclade;
  • taxa in a state that is not allowed;
  • whether the backbone was preserved or not, with an estimate of shift in branch length (attributed to rounding errors in floating-point numbers).

In addition to the printed summary, the function returns a table with one row per taxon and per grafted phylogeny (columns target_ok, excluded_ok, states_ok and ok) and, as attributes, the summary of each phylogeny (phylogenies) and of the backbone preservation.

The grafting functions are designed to always respect the constraints: this check is a safety net to run on the final outputs, particularly when the inputs are complex (many maps, ranges, several traits).

3/ Where and when: extract_grafting_info()

extract_grafting_info() describes where and when each lineage was grafted in each grafted phylogeny.

It reports:

  • the parent clade (parent_node and parent_tips: the clade of the backbone on which the lineage was grafted);
  • the graft age (when the lineage branched from the backbone);
  • the divergence age (when it branched from its closest relative, which can be another grafted taxon);
  • and the state of the lineage, when a stochastic map is available.

It returns one row per taxon and per phylogeny, with the map, simulation and seed that produced it, so the outputs of many simulations and maps can be summarized with aggregate(), and each phylogeny can be reproduced alone with its seed (see vignette("handle_uncertainty")).

# ------ Grafting information with one stochastic map ------ #

# Extract grafting information
info_one <- extract_grafting_info(phy_grafted = grafted_one, missing_taxa_list = taxa_list_fixed,
                                  phy_backbone = toy_backbone)
# Inspect the first rows describing the results for the first simulation (among 10)
head(info_one[, c("simulation", "Taxon_name", "parent_tips", "graft_age", "divergence_age", "tip_state")], 4)

4/ Sampling fractions: extract_sampling_info()

When the total richness of some clades is known, it can be provided as inputs (total_richness_per_clades) to account for unsampled species (not in the backbone, nor listed to be grafted) when fitting BD models to estimate divergence ages of taxa to be grafted: see Section 3 in vignette("graft_missing_taxa") for an illustration of the effect.

However, the grafted taxa raise the sampling fraction (i.e., the proportion of species present in the grafted tree vs. all species) of the clades in which they are grafted. Since the grafted taxa are placed at random within their target clades, the effective sampling fraction of nested clades varies among the simulations. extract_sampling_info() returns, for each clade with a total richness provided, and each grafted phylogeny:

  • the number of backbone species;
  • the number of grafted species;
  • the number of unsampled species;
  • and the effective sampling fraction after grafting.

This is the way to explore how much the grafting procedure may have helped to even sampling across clades. Moreover, clade-specific sampling fractions can be used as inputs in downstream analyses such as diversification models (e.g., BAMM) to still account for the unsampled species in later steps of the analytic pipeline.

Here, we graft 6 taxa within Family_B, in the state “blue” (they land in Subfam_B1, Subfam_B2 or elsewhere), and 2 taxa within Gen_1, with the total richness of four clades. Subfam_B1, Subfam_B2 and Gen_1 are nested within Family_B, and Gen_1 within Subfam_B1.

We use 10 simulations to account for the uncertainty in the grafting procedure (see vignette("handle_uncertainty")).

Compare clade-specific sampling fractions before grafting and after grafting

Here, we use the output of extract_sampling_info() to explore how much the grafting procedure may have helped to even sampling across clades. We directly compare the sampling fraction of each clade before grafting, and after grafting.

# Compute pre-grafting sampling fraction based on backbone species only 
pre_grafting <- unique(sampling_one[, c("Clade_name", "total_richness", "nb_backbone_species")])
pre_grafting$pre_grafting <- round(pre_grafting$nb_backbone_species / pre_grafting$total_richness, 2)

post_grafting <- aggregate(sampling_fraction ~ Clade_name, data = sampling_one,

merge(pre_grafting[, c("Clade_name", "total_richness", "pre_grafting")], post_grafting, by = "Clade_name")

Note that the sampling fraction that the diversification models use to draw the ages is the one of the clade at the time of grafting, shown in the next Section 5 below addressing diversification models, and not the final effective sampling fractions that may be altered by taxa being grafted in nested clades later in the process.

5/ Diversification models: extract_BD_model_summary()

The divergence ages of the grafted taxa are drawn from birth-death (BD) models fitted on the clade they are grafted in (see vignette("graft_missing_taxa")).

With phylograftR::graft_missing_taxa(), a model is fitted per target clade, and used by all the taxa of the target clade, whatever their stem availability or excluded subclades. With phylograftR::graft_missing_clades(), a model is fitted per missing clade, i.e., per sister clade.

Each model is fitted on the tree as it stands when its group of taxa is processed, not on the backbone: it includes the taxa already grafted by earlier groups in the same simulation, and its sampling fraction accounts for the taxa still waiting to be grafted in the clade. As a consequence, the models are not necessarily identical across simulations and maps:

  • a model fitted before any other grafting in its clade (a single group of taxa, or the innermost of several nested groups) only depends on the backbone: it is the same in all simulations and maps. This is the case for the two taxa grafted in Gen_1 in our example from Section 4 above.
  • a model fitted on a clade that contains taxa grafted earlier (e.g., a group grafted in Family_B after the taxa grafted in Gen_1) depends on where and when those taxa were grafted: it varies across simulations, and across stochastic maps.
  • when taxa and clades are grafted successively with graft_missing_taxa_and_clades(), the models of the second step include the taxa grafted in the first one, so they vary across simulations.

With return_BD_model_summary = TRUE, the grafting functions record the BD models, and extract_BD_model_summary() returns one row per fitted model, for each simulation and map.

Here, we use the outputs of the previous section, with total richness, to report on the BD model fits used during the grafting process for each simulation:

How to read the table:

  • Clade used: initial_clade_tips is the target clade of the taxa, and fitted_clade_tips the clade on which the model was fitted. They differ (enclosing = TRUE) when the target clade has fewer tips than min_tips: here, the 3-tip Gen_1 is replaced by an enclosing clade (see vignette("graft_missing_taxa") for how to tune min_tips).
  • Sampling fraction: rho is the sampling fraction of the model: the species of the fitted clade over its total richness. n_pending is the number of taxa to graft within the clade (not counted as sampled) and n_unsampled the number of unsampled species that the total richness adds (see Section 4 above).
  • Variation across simulations and maps: the summary above shows that the model of the Gen_1 taxa is the same in the 10 simulations (1 distinct fit: it is fitted on the backbone), while the model of the Family_B taxa is different in each simulation (10 distinct fits): Family_B contains the Gen_1 taxa grafted before, at different ages in each simulation, which changes the rates b and d of the fit. The sampling fraction rho is the same because the number of tips and the total richness of the clade do not change.
  • Rates: b and d are the speciation and extinction rates, net_diversification is b - d, and relative_extinction is d / b. The extinction rate can be adjusted, as shown by d_adjustment: "none" (the fitted value is used), "capped" (the fitted d was too close to, or above b, and was capped to 99% of b), or "set_to_0" (a negative d was set to 0). A "capped" or "set_to_0" model means that the data support very high or null extinction: it is common with small clades, and it is a flag to look at the tree and the sampling fraction before trusting the rates.
  • Warnings: fits on small or very incomplete clades may print NA/NaN function evaluation warnings from the optimizer. They are not errors: the model is still fitted, but check that the rates look sensible.
